# 工具箱：电子六线谱 PDF 转 MusicXML 设计

## 目标

在 RockRoll 中新增独立工具箱，允许用户在浏览器本地选择清晰的电子吉他六线谱 PDF，分析五线谱与 TAB 的结构，并导出可由 Guitar Pro 8 打开的 MusicXML。

首个验收样例是用户本地的 `endless rain.pdf`。该文件不进入仓库，也不上传到 Supabase。

## 产品边界

- 输入仅限清晰电子 PDF，不支持扫描件或照片。
- 首版仅支持单吉他轨、六弦标准调弦 E A D G B E、五线谱与 TAB 配对。
- 全程浏览器本地处理，不上传、不持久化、不调用在线转换服务。
- 输出为 `.musicxml`，由 Guitar Pro 8 打开后另存为 `.gp`。
- 识别不确定时必须显示警告，不得静默猜测。
- 不引入 Tauri、后端 worker、队列、数据库表或 Supabase Storage。

## 技术方案

采用 `pdfjs-dist@4.10.38` 动态读取 PDF。该版本兼容项目当前 Node 20/Vite 8，使用 Apache-2.0 许可证。工具箱路由打开前不加载 PDF.js。

解析流程分为四层：

1. `pdf.service.ts` 负责文件类型、大小、页数、文本项和绘图指令读取。
2. `tab-analyzer.ts` 负责识别电子谱特征、标题、速度、拍号、小节编号、TAB 文本和诊断警告。
3. `musicxml.service.ts` 负责将已确认的乐谱模型序列化为 MusicXML；未识别音符的小节使用明确的整小节休止占位并产生警告。
4. `ToolboxPage.tsx` 负责文件选择、分析状态、摘要、警告和下载。

第一实施阶段先建立安全的纵向切片：能识别电子 PDF、提取页数/标题/速度/拍号/小节范围，并生成结构合法的 MusicXML 骨架。随后再按测试扩展弦号、品位、节奏和技巧识别。

## 阶段 2：字符串 / 品位几何定位

阶段 2 仅为清晰电子六线谱建立可审计的几何定位结果，不把结果写入 MusicXML，也不推断音符时值、节奏、连音、推弦、滑音或其他技巧符号。

### 输入与输出

- 输入继续使用 `PdfDocumentSnapshot.textItems` 的文本、页码、坐标、宽高与字号；不读取用户 PDF 之外的外部数据。
- 每个候选 TAB 系统由连续小节编号的横向范围和六条等距字符串基线构成。
- 只接受位于 TAB 系统范围内、文本内容为 `0` 至 `24` 的候选品位；单字符和双字符数字均以同一文本项处理。
- 每个通过定位的候选输出页码、小节号、从低音 E 到高音 E 的弦序（1 至 6）、品位、原始坐标与 `high` 或 `medium` 置信度。
- 不能唯一归属到字符串、未落入可靠小节区间、超出 `0` 至 `24`，或与标题、小节编号、速度数字等冲突的文本必须拒绝，并累计诊断警告；不得静默猜测。

### 算法边界

1. 按页码和从上到下的坐标顺序处理文本项，先以既有连续小节编号为锚点切分候选 TAB 系统。
2. 在每个系统中寻找六个垂直分层且近似等距的字符串文本行；仅当六条基线的间距落在允许误差内时，系统才可用于品位定位。
3. 将候选品位文本的垂直中心点映射到最近字符串基线；只有距离不超过字符串间距的限定比例时才接受。
4. 按小节编号锚点的 `x` 坐标划分小节区间，并将候选品位按 `x` 中心点归入区间；不推断小节内的时间顺序以外的音乐语义。
5. 矢量绘图数量仅继续用于电子 PDF 的诊断，阶段 2 不依赖线条路径重建字符串或节奏。

### 置信度与兼容性

- `high`：系统具有六条等距基线，候选处于唯一字符串容差和唯一小节区间内。
- `medium`：系统与字符串归属可靠，但候选处于相邻小节锚点的边界容差内；结果保留并附带警告。
- 未达到上述条件的候选不进入定位结果；阶段 1 的安全 MusicXML 继续输出整小节休止占位，确保既有下载行为不改变。
- 首个验证对象仍为本地 `endless rain.pdf`；文件不复制进仓库、不上传，也不作为自动化测试夹具。

## 阶段 3：小节内候选时序

阶段 3 只把同一小节内已定位的 `TabFretPosition` 按横向坐标聚合为从左到右的候选事件列。它不把几何列解释成节拍、时值、休止、音高、和弦名称或可播放音符。

### 数据边界

- 输入为同一页、同一小节的高/中置信度 `TabFretPosition`；不重新读取 PDF，也不分析矢量线条或文本以外的信息。
- `TabFretEvent` 包含页码、小节号、顺序索引、事件的代表 `x` 坐标、弦/品位候选集合和 `high` / `medium` 置信度。
- 横向距离小于字符串间距推导出的固定比例的候选归为同一事件列；同一列可包含多个弦，表示“同时出现”，但不声称它是和弦或具体节奏位置。
- 事件按 `x` 从左到右排序；跨页、跨小节、跨系统的候选绝不合并。
- 同一事件列内若同一弦出现多个不同品位，或相邻列间距过小以至无法稳定切分，保留候选并降为 `medium`，同时产生诊断警告。

### 兼容性

- 页面仅可显示“已定位事件列数量”和几何警告；不提供事件编辑器或播放控件。
- MusicXML 继续忽略事件列，保留阶段 1 整小节休止骨架。
- 下一阶段若要识别节奏时值，必须单独设计可信的明确符号来源与整小节回退机制；不能从横向间距直接猜测音符时值。

## 阶段 4：PDF 矢量六线基线定位

阶段 4 用电子 PDF 的矢量路径坐标识别 TAB 系统的六条字符串基线，解决品位文本没有覆盖全部六弦时无法建立基线的问题。它不改变 PDF 文件的本地处理边界，不识别节奏、技巧或音符。

### 输入与输出

- `pdf.service.ts` 在保留当前文本、图片和绘图总数输出的同时，新增每页归一化的线段几何；只保留路径中的起点、终点和页码，不保存源 PDF。
- `TabStaffSystem` 包含页码、横向范围、六条从低音 E 到高音 E 的字符串基线、平均弦距和置信度。
- 只接受近似水平、长度相近、纵向等距且形成连续六线组的矢量线段；五线谱、装饰线、单条小节线和不完整组合必须拒绝。
- 已有 `locateTabFrets` 优先使用 `TabStaffSystem` 归属字符串，缺少可靠矢量系统时才保留当前文本行回退；两种来源都无法定位时继续返回警告和空结果。

### 可靠性规则

- 一条基线只由多个共线或轻微断开的水平线段组成；线段之间允许小间隙，但不能跨越不同系统的纵向区域。
- 六条基线的长度偏差和相邻弦距偏差必须低于明确阈值；不满足阈值则不输出系统。
- 基线横向范围必须覆盖相应小节编号锚点之间的品位文本区域；只有落在范围内的品位候选才可归属。
- 每个 `TabStaffSystem` 都带 `high` 或 `medium` 置信度；`medium` 系统的品位结果保留，但附加“请复核”诊断。

### 兼容性

- PDF 仍通过浏览器本地动态加载与释放；不上传、不持久化、不修改 Supabase。
- 页面只追加基线系统数量或诊断，不改变下载按钮条件。
- MusicXML 继续忽略字符串基线、品位候选和事件列，保持阶段 1 安全休止骨架。

## 阶段 5：真实电子谱明确节奏符号拓扑

阶段 5 从与 TAB 配对的五线谱中读取谱面已经明确表达的节奏符号。真实电子 PDF 可能把同一个符号表达为绘制路径、复合轮廓、多个独立绘制操作或音乐字体字形，因此不能假设“一条路径就是一个音符”，也不能依赖单一导出器的固定外形模板。

本阶段采用“矢量路径拓扑 + 可靠音乐字体字形”双通道证据，统一进入局部符号拓扑图。横坐标只用于符号归组、事件排序、小节归属和与 TAB 事件列唯一配对；不得根据 TAB 横向距离、相邻事件间距、平均间距或小节宽度推断时值。

### 支持范围

- 支持全音符、二分音符、四分音符、八分音符和十六分音符。
- 支持对应休止符和一个附点。
- 支持空心 / 实心符头、符干、单 / 双符尾、共享或局部连梁、多符头共享一根符干。
- 允许连梁倾斜、主梁与次梁长度不同、复合轮廓由多个子路径或多个绘制操作组成。
- 不支持三连音及其他连音组、延音线、跨小节连梁、装饰音、多声部重叠、演奏技巧、扫描件、播放、人工时值编辑和专有 `.gp` 输出。

### 双通道 PDF 证据

- `pdf.service.ts` 在现有文本项和直线段之外，保留绘制后的矢量形状：子路径、闭合状态、填充规则、绘制方式、可用线宽、变换后坐标和边界。
- 一个绘制形状可以包含多个子路径；适配器保留来源关系，不在 PDF.js 层决定它属于一个还是多个音乐符号。
- 现有 `PdfLineSegment` 继续服务于六线谱基线定位，新增符号证据不得改变其行为。
- 文本项补充可获得的字体标识与字体族。只有字符映射和字体来源都能可靠解释时，才生成带明确语义的音乐字形证据。
- 私有区字符、未知字体或无法稳定映射的字形保留为未知证据，只能产生诊断，不能单独确定时值。
- 不保留完整 PDF 操作列表，不记录或输出 PDF 原始内容。

### 规范化图元与拓扑图

绘制形状和字形证据先按配对五线谱的平均谱线间距归一化，再转换为内部 `NotationPrimitive`。图元仅在同页、同一配对系统内建立关系，禁止跨系统连接。

内部图元包括：

- `contour`：开放 / 闭合轮廓、孔洞和复合填充区域。
- `segment`：符干、短梁和其他线性候选。
- `glyph`：具有可靠音乐语义的字体字形。
- `unknown-glyph`：只参与冲突和不支持诊断。

拓扑边包括 `touches`、`intersects`、`contains`、`aligned-with` 和 `incident-to`。识别器根据关系组合符头、符干、连梁、符尾、附点和休止符，不根据路径数量或绘制调用次数组合事件。

### 证据等级与时值判定

- 强拓扑证据：闭合轮廓、孔洞、符干连接、连梁层或符尾连接等明确结构。
- 强字形证据：字体和字符映射可靠、语义明确的音乐字形。
- 弱证据：未知字形、单独边界框、近似外形或仅有位置相似。
- 每个可导出事件必须至少包含一种强证据。强字形与强拓扑同时存在时必须一致；冲突时不选择其一，相关小节整体回退。
- 弱证据只能辅助局部归组或产生诊断，不得直接给出时值。

时值规则：

- 空心符头且没有相连符干：全音符。
- 空心符头与唯一符干相连：二分音符。
- 实心符头与唯一符干相连，且符干没有连梁或符尾：四分音符。
- 实心符头的符干连接一个连梁层或一个符尾：八分音符。
- 实心符头的符干连接两个独立连梁层或两个符尾：十六分音符。
- 多个符头共享一根符干时形成一个同节奏事件，不按符头数量重复累计时值。

空心符头可以由 `evenodd` / `nonzero` 孔洞、嵌套轮廓、描边轮廓或可靠字形语义表达；不得简单把 `stroke` 等同于空心、把 `fill` 等同于实心。

### 共享连梁、符尾、附点与休止

- 先建立连梁组，再计算每根符干实际连接的连梁层数。次梁只影响与其明确相接的符干，不能根据同组其他音符类推。
- 连梁允许倾斜和分段，但必须与符干形成唯一拓扑连接；只是靠近时降为中等置信度并回退小节。
- 符尾必须与符干端部唯一连接；附近无关曲线不能计入符尾数量。
- 附点允许使用“位于符号右侧”的局部附着关系，窗口按谱线间距归一化。候选必须唯一且垂直位置合理；无法与断音点区分时回退。
- 休止符优先使用可靠字形语义；路径识别使用归一化拓扑模板。未知字形不能仅凭矩形边界或所在谱线猜测休止时值。

### 识别与配对流程

1. 定位五线谱系统及其下方唯一对应的 TAB 系统。
2. 在每个配对系统内规范化路径和字形证据，建立局部拓扑图。
3. 解析明确节奏事件，并记录证据来源、冲突和不支持结构。
4. 使用横坐标完成事件排序、小节归属和与 `TabFretEvent` 的唯一配对；横坐标不参与时值判定。
5. 同一小节内的节奏事件按拍号换算后必须恰好填满容量。
6. 只有全部事件为高置信度、非休止事件全部唯一配对、且容量完全合法的小节可以导出真实音符。

### 输出数据模型

```ts
type RhythmDuration = 'whole' | 'half' | 'quarter' | 'eighth' | '16th';

interface RecognizedRhythmEvent {
  page: number;
  measureNumber: number;
  tabEventOrder: number | null;
  duration: RhythmDuration;
  dots: 0 | 1;
  isRest: boolean;
  confidence: 'high' | 'medium';
  sourceSymbols: string[];
}

interface MeasureRhythmResult {
  measureNumber: number;
  status: 'recognized' | 'fallback';
  events: RecognizedRhythmEvent[];
  warning: string | null;
}
```

- 原始路径、规范化图元和拓扑节点属于内部分析细节，不写回 `TabFretEvent`。
- `tabEventOrder` 仅在非休止事件唯一配对后填写；休止符为 `null`。
- `status = 'recognized'` 时所有事件必须为高置信度且整小节容量合法；否则 MusicXML 不得消费候选事件。

### 兼容等级与整小节回退

- `recognized`：强证据明确、拓扑唯一、TAB 配对唯一、整小节容量合法，可导出真实音符。
- `diagnostic`：存在未知字形、中等置信度、邻接但未连接、或不支持结构，只显示诊断。
- `fallback`：小节不能安全导出，继续使用阶段 1 的整小节休止占位。

以下任一条件触发整小节回退：

- 找不到可靠的五线谱 / TAB 上下配对。
- 字形语义与路径拓扑冲突。
- 符头、符干、连梁层、符尾、附点或休止符归属不唯一。
- 出现连音组、延音线、跨小节连梁、装饰音或多声部重叠。
- 任一非休止节奏事件无法唯一对应 TAB 事件列。
- 事件总时值不足、超出或不符合当前拍号容量。

不允许部分小节写入真实音符后自动补休止，也不允许通过事件间距补齐缺失节奏。

### MusicXML 与页面规则

- 已识别小节使用确认后的节奏事件和 TAB 弦 / 品位生成 MusicXML；回退小节保持整小节休止占位。
- 同一导出可以混合已识别和回退小节，但页面及 MusicXML credit 必须列出回退小节。
- `divisions` 覆盖十六分音符及单附点，不能继续固定为 `1`。
- 页面显示已检查、可安全导出和已回退的小节数量，以及每小节状态和简短原因。
- 不展示置信度百分比，不提供逐音符编辑、拖拽时间轴、播放或技巧设置。
- PDF 无可靠五线谱或没有可用强证据时，保留原有安全休止骨架下载。

### 测试与验收

- 适配器夹具覆盖复合子路径、多次建路后统一绘制、`nonzero` / `evenodd`、填充 / 描边 / 填充描边、曲线、闭合、变换栈、路径清理、可靠字形与未知字形。
- 拓扑夹具覆盖路径单通道、字形单通道、双通道一致 / 冲突、空心符头多种表达、共享倾斜连梁、局部次梁、单 / 双符尾、多符头共享符干、附点 / 断音点歧义和休止符。
- 拒绝夹具覆盖装饰线、歌词、TAB 线、小节线、未知字形、不支持符号和跨系统候选。
- 小节测试覆盖唯一 TAB 配对、歧义配对、合法容量、容量不足 / 超出、多声部和整小节回退。
- MusicXML 测试确认只有完整合法的小节写入真实音符；页面测试覆盖统计、状态、警告和混合导出说明。
- 自动化测试只使用人工构造的规范化证据，不复制或提交真实 PDF。真实 PDF 仅在用户明确允许时做浏览器本地只读验证。

## 页面与交互

- 主导航新增“工具箱 / Toolbox”。
- 页面第一视觉是一个类似谱架工作台的文件投放区，保持 RockRoll 现有煤黑、酒红、琥珀色体系。
- 选择文件后立即在本地分析，显示文件名、页数、识别到的小节范围、速度、拍号和矢量对象数量。
- 不支持的扫描 PDF、加密 PDF、空 PDF、非 PDF 或超限文件显示可操作错误。
- 分析完成且存在小节结构时启用“下载 MusicXML”。
- 下载文件名来自 PDF 文件名，扩展名替换为 `.musicxml`。

## 错误处理

- 最大文件大小 20 MB，最大页数 20 页。
- PDF 没有可提取文本或矢量绘图时，判定为扫描件并停止转换。
- 未识别速度时默认输出 120 BPM，但在界面和 MusicXML 中记录警告。
- 未识别拍号时默认输出 4/4，但记录警告。
- 未识别到小节编号时不允许下载。
- 对象 URL 下载后立即释放。

## 测试与验收

- 单元测试覆盖文件校验、标题/速度/拍号/小节提取、MusicXML 转义和骨架生成。
- 页面测试覆盖本地分析状态、错误提示、摘要、警告和下载按钮。
- 路由测试覆盖 `#toolbox`，导航测试覆盖入口与激活态。
- 使用 `endless rain.pdf` 做只读验证：4 页、可提取文本、无整页图片、存在大量矢量绘图、识别到 1-18 小节和 92 BPM。
- MusicXML 必须可由 XML 解析器读取，并能由 Guitar Pro 8 打开；复杂音符识别完成前，骨架中的休止占位必须明确标注为未识别，不能伪装成成功转谱。
