# 私人音乐档案馆与练琴记录系统设计方案

## 1. 产品定位

这是一个云端优先的私人音乐档案馆与练琴记录系统，面向音乐爱好者、吉他手和乐手型听众。产品把“听音乐、研究音乐、练习音乐”放进同一个私密空间，让曲目既可以作为音乐档案节点，也可以作为练琴对象长期沉淀。

第一版不做公开社区和分享功能，所有内容默认私密，只服务个人跨设备同步。

## 2. 核心理念

产品的中心不是单独的练琴打卡，也不是复制一个公开音乐百科，而是围绕“曲目”建立个人音乐宇宙：

```text
外部音乐资料 → 待整理收件箱 → 个人音乐档案 → 曲目练习记录 → 视频/乐谱/复盘沉淀
```

自动抓取的信息只作为底稿，最终档案由用户整理、校对、标注和补充。系统需要明确区分“外部来源数据”和“用户个人笔记”，避免后续同步更新覆盖用户自己的理解。

## 3. 目标用户

- 想系统记录练琴过程的吉他手或其他乐手。
- 喜欢研究艺人、专辑、风格、音乐史脉络的音乐爱好者。
- 希望把视频、乐谱、练习笔记和音乐资料放在同一个地方的人。
- 需要电脑端整理资料、手机端快速记录练习的跨设备用户。

## 4. MVP 范围

### 4.1 第一版包含

- 账号登录与云端数据同步。
- 曲目库：歌曲/曲子作为核心节点。
- 练琴记录：日期、时长、BPM、练习段落、问题、复盘。
- 视频与文件上传：练琴视频、音频、PDF、GP、图片谱、伴奏。
- 音乐档案：艺人、专辑、风格、年份、乐手、唱片公司。
- 外部资料搜索导入：优先接入 MusicBrainz，后续补 Discogs 和 Spotify。
- 待整理收件箱：导入结果先形成草稿，由用户确认后入库。

### 4.2 第一版不包含

- 分享链接或公开主页。
- 社区、关注、评论、点赞。
- PDF 自动转 Guitar Pro。
- AI 自动生成音乐百科事实。
- 视频剪辑、逐帧批注或复杂片段管理。
- 原生 iOS/Android App。

## 5. 产品结构

### 5.1 首页 / Backstage

首页是用户每天进入产品的练习室控制台，突出今天要练什么、最近整理了什么、还有哪些资料待处理。

主要区域：

- 今日练习：当前曲目、目标时长、BPM、练习重点。
- 最近视频：最近上传的练习视频和关联曲目。
- 待整理资料：外部导入后还未确认的艺人、专辑、曲目。
- 最近研究：最近查看或编辑的艺人、专辑、风格。
- 本周概览：练习时长、练习天数、曲目数量。

### 5.2 曲目库 / Songs

曲目是系统的核心实体。每首曲目既连接音乐档案，也连接个人练习。

曲目详情包含：

- 基础信息：标题、艺人、专辑、年份、风格、难度、状态。
- 练习记录：按时间展示每次练习。
- 文件资料：PDF、GP、图片谱、伴奏、外部链接。
- 视频历史：按日期查看练习视频。
- 关联关系：艺人、专辑、风格、乐手、版本。
- 个人笔记：听感、练习心得、编曲分析、技巧难点。

### 5.3 音乐档案 / Archive

音乐档案用于整理个人音乐知识库，不限定摇滚，也覆盖爵士、布鲁斯、放克、金属、古典、融合等风格。

实体类型：

- 艺人：个人、乐队、组合。
- 专辑：录音室专辑、现场专辑、EP、精选集。
- 风格：摇滚、爵士、布鲁斯、金属、放克等，可多级分类。
- 乐手：吉他手、贝斯手、鼓手、键盘手、制作人等。
- 历史事件：发行、巡演、阵容变化、重要现场、风格转折。

### 5.4 收件箱 / Inbox

收件箱负责把外部资料变成可控草稿，避免错误数据直接污染个人档案。

流程：

```text
输入关键词
↓
搜索外部数据源
↓
展示候选结果
↓
用户选择正确条目
↓
生成草稿
↓
用户确认、编辑、打标签
↓
写入个人档案
```

### 5.5 资料库 / Library

资料库统一管理所有上传文件，但文件最终都应尽量关联到曲目、练习记录或档案实体。

文件类型：

- 视频：练琴视频、现场片段、教学片段。
- 音频：录音、伴奏、参考音源。
- 乐谱：PDF、图片谱、GP、MusicXML。
- 链接：YouTube、Bilibili、Spotify、Discogs、MusicBrainz 等外部地址。

## 6. UI 设计语言

### 6.1 设计方向

整体方向为 `Backstage Archive / 私人后台档案馆`。视觉不做廉价黑红骷髅风，而是从音乐文化物件中提取设计语言：唱片封套、乐谱批注、后台通行证、磁带标签、音箱旋钮、VU 表、演出海报、Real Book 页边注。

### 6.2 色彩

- 炭黑：主背景，营造后台和练习室氛围。
- 烟灰：卡片、分区和弱层级背景。
- 旧纸白：正文和乐谱感内容区域。
- 深酒红：重点操作、状态强调。
- 舞台琥珀：练习进度、REC 状态、当前焦点。
- 金属银：边框、数据标签、器材质感。

### 6.3 组件隐喻

- 今日练习卡像一台练习音箱面板。
- 练习时长可以用 VU 表或电平条表达。
- 上传状态可以使用 REC 灯。
- 曲目卡片像唱片封套。
- 导入草稿像后台通行证或档案标签。
- 资料文件像乐谱夹和磁带标签。

### 6.4 设计原则

- 美观优先，但不能牺牲练琴时的快速记录。
- 摇滚元素作为细节和质感，不作为全局噪音。
- 信息密度可以比普通打卡 App 更高，但关键操作必须清晰。
- 移动端以快速记录为主，桌面端以整理档案为主。

## 7. 推荐技术架构

### 7.1 应用形态

第一版使用 Web/PWA。桌面端用于整理音乐档案和文件，移动端用于练琴时快速记录与上传。

### 7.2 前端

- Web/PWA 单页应用。
- 响应式布局，优先保证桌面与手机浏览器体验。
- 需要支持文件上传进度、离开页面前提醒、表单草稿保存。

### 7.3 后端与云服务

推荐第一版使用 Supabase：

- Auth：账号登录。
- PostgreSQL：关系型音乐档案与练习数据。
- Row Level Security：用户数据隔离。
- Storage：视频、音频、PDF、GP、图片谱等文件。
- Edge Functions 或独立轻量服务：外部音乐资料搜索与导入。

后续如果产品复杂度提升，可以迁移到自建后端、PostgreSQL、对象存储和任务队列组合。

### 7.4 外部数据源

- MusicBrainz：第一优先级，适合艺人、专辑、曲目、发行信息和关系数据。
- Discogs：第二阶段接入，适合唱片版本、厂牌、介质和收藏信息。
- Spotify：作为补充数据源，适合封面、流媒体链接和搜索体验，不能作为唯一事实来源。

外部数据请求需要缓存和限流。MusicBrainz 公共 API 需要控制请求频率，导入任务应通过队列或节流器执行。

## 8. 初版数据模型

### 8.1 用户与权限

- `users`：用户基础信息。
- `profiles`：用户偏好、显示名、默认练习设置。

所有业务数据都需要带 `user_id`，通过权限策略保证用户只能访问自己的数据。

### 8.2 音乐档案

- `artists`：艺人/乐队。
- `albums`：专辑。
- `tracks`：曲目。
- `genres`：风格。
- `musicians`：乐手。
- `labels`：唱片公司。
- `external_sources`：外部来源 ID、来源类型、原始链接、同步时间。

### 8.3 练琴记录

- `practice_sessions`：一次练习记录。
- `practice_targets`：练习目标，例如速度、段落、技巧点。
- `practice_notes`：复盘、问题、心得。

### 8.4 媒体与文件

- `media_assets`：视频、音频、PDF、GP、图片谱等文件元数据。
- `media_links`：文件与曲目、练习记录、艺人、专辑等实体的关联。

### 8.5 导入草稿

- `import_jobs`：一次搜索或导入任务。
- `import_candidates`：外部候选结果。
- `import_drafts`：用户选择候选后生成的待确认草稿。

## 9. PDF 乐谱转 GP 路线

PDF 转 GP 不进入第一版 MVP，但作为长期工具箱方向保留。

建议路线：

```text
阶段 1：PDF/图片谱上传、归档、曲目关联
阶段 2：手动标注段落、难点、小节、版本
阶段 3：尝试 OMR 识别并导出 MusicXML
阶段 4：人工校对 MusicXML
阶段 5：探索 MusicXML 到 GP 兼容格式的转换
```

该功能难点在于乐谱识别准确率，尤其是吉他谱、节奏、连音、反复记号、指法和不同排版格式。第一版应避免把核心价值押在自动识别上。

## 10. 隐私与安全

- 所有内容默认私密。
- 第一版不提供公开分享链接。
- 视频、音频、乐谱文件需要绑定用户权限。
- 外部资料导入只保存公开来源元数据和用户主动确认的内容。
- 不在代码、日志或前端暴露密钥。
- 文件上传需要限制大小、类型和用户配额。

## 11. 后续路线图

### 阶段 1：可日用 MVP

- 登录。
- 曲目库。
- 练琴记录。
- 文件上传。
- 基础音乐档案。
- MusicBrainz 搜索导入。
- 待整理收件箱。

### 阶段 2：档案增强

- Discogs 数据补充。
- Spotify 链接补充。
- 艺人、专辑、风格关系图。
- 更强的标签和筛选。
- 练习统计和进步时间线。

### 阶段 3：练琴增强

- 视频缩略图和基础转码。
- 练习片段标记。
- A/B 练习对比。
- 节拍器、调音器、速度训练辅助。

### 阶段 4：乐谱实验室

- PDF/图片谱标注。
- OMR 识别实验。
- MusicXML 导入导出。
- GP 转换链路探索。

## 12. 成功标准

第一版成功不以功能数量衡量，而以是否能形成稳定使用闭环衡量：

- 用户可以在手机上快速记录一次练琴。
- 用户可以上传并回看练琴视频。
- 用户可以把练习记录绑定到具体曲目。
- 用户可以从外部数据源导入音乐资料草稿。
- 用户可以把导入资料整理成自己的音乐档案。
- 用户可以在电脑和手机之间同步查看数据。
